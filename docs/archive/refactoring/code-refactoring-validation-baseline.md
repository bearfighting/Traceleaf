## 主要缺测风险

- Dashboard 创建/密钥单测尚未证明真实 route 与服务在并发、请求超时、跨标签状态下的一致性；E2E 需要覆盖实际 onboarding/设置链路。
- Collector/Analytics API/Processor 的真实 PostgreSQL ignored tests 仍是持久化、锁、事务、generation 和故障恢复的必要证据；纯单测不能替代。
- `pnpm check` 的 clippy/workspace 边界与全部 package typecheck/lint 尚未作为本次候选基线运行；统一 CI 脚本仍是合并回归命令。
- CSS 没有独立样式测试；修改全局加载/选择器后需使用 dashboard build 与浏览器 viewport/layout 检查。
- E2E runner 单测验证编排参数和锁，但不验证 suite 失败路径是否完成截图、日志采集及容器清理；真实失败注入/诊断验证留待 E2E 拆分前。

## 仓库统一检查和 CI 入口

- `pnpm check` → `tooling/ci/check.sh`：Cargo fmt、workspace clippy、Analytics API module-boundary test、package typechecks/eslint、playground/dashboard typecheck/lint、格式检查。
- `pnpm test` → `tooling/ci/test.sh`：workspace cargo tests、contract/parity tooling、package builds/tests、dashboard tests 及 Node tooling/support 单测。
- `pnpm build` → `tooling/ci/build.sh`：workspace Cargo build、package、playground、dashboard builds。
- `pnpm format:check`：统一格式检查；文档额外使用 `pnpm format:check:docs`。
- `pnpm test:integration` → PostgreSQL migration + ignored storage/runtime/processor/API tests。
- E2E suite 命令在根 `package.json`；CI workflow `.github/workflows/quality.yml` 分 job 安装依赖、启动 suite 并 teardown。候选单测和必要的 E2E suite 必须针对改动选择，不能以 `pnpm test` 已通过声称浏览器端到端覆盖。

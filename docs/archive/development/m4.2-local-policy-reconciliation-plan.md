## Goal and approved local state

Reconcile every local Site/environment that is intended to collect against the PostgreSQL policy. Keep historical and test Registry identities without ingest policies unless an explicitly approved local runtime source requires collection.

The approved local ingest target is `site_example/development`: enabled, the three localhost Origins shared by the development seed and Collector development TOML, a limit of 600 events/minute, and one existing key digest matching the effective local seed and Playground keys. Keep `site_playground` definitions-only, with no ingest policy. Keep `site_example/production` and TOML-only `site_disabled/production` absent from PostgreSQL policy storage.

The absence of a DB policy does not yet prevent the current Collector TOML fallback from authorizing `site_example/production`. Removing that runtime path and proving missing-policy fail-closed behavior belong to M4.4.

## Execution procedure

1. Start PostgreSQL only and capture a fresh read-only snapshot of Registry lifecycle, policies, Origins, limits, key counts, audit, effective Compose mappings and Collector TOML policy entries. Do not start Collector, dev-seed, Playground or Dashboard during reconciliation.
2. Compare configured development key values to DB digests in memory. Retain only boolean match results and counts; never print or persist keys, digests, admin tokens or credential-bearing database URLs.
3. Preserve the approved state when values match. If an approved non-key policy field has drifted, take and verify a fresh backup, then use the existing authenticated policy API with the current `If-Match` ETag. Do not write policy data with SQL. A missing expected policy, unexpected policy, unexpected active Site mapping or key mismatch stops that item for owner review; do not create/delete policies or rotate keys automatically.
4. If an API update is required, run Analytics API with the base `compose.yaml` processing/storage profiles without `compose.dev.yaml`; the development overlay makes Analytics API depend on `dev-seed`. Keep Collector and seed stopped. Re-read policy, version, Origins, limit, key count and audit after the update.
5. Record all current TOML paths for missing DB policies as M4.4 follow-up. M4.2 verifies DB absence and does not claim that those policies are already denied by the running Collector.

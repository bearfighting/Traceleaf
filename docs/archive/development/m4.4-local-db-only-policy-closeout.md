# M4.4 Local DB-only Policy Closeout

Date: 2026-10-01  
Target: local development database only

## Result

Collector Site/environment authorization policy now comes only from PostgreSQL. The runtime joins policies to active `site_registry` rows and replaces the in-memory snapshot after successful refresh. Deleted policies and archived Sites are removed, and their applied-state rows are cleared for this Collector instance so the API does not report them as current; disabled policies remain explicitly denied. During a temporary database failure, the last valid database snapshot remains available and is marked stale when status reporting is reachable. A missing policy never falls back to a TOML sample.

Collector no longer accepts `--config` or `COLLECTOR_CONFIG`. Listener binding remains configurable through CLI options. Compose files and `.env.example` no longer advertise a Collector policy file. The TOML samples are retained as migration/test references and have no runtime authorization effect.

## Local policy postflight

The local PostgreSQL service was started temporarily for a read-only query and stopped afterward. The query confirmed:

- `site_example/development` has active DB policy version 2, enabled, with the three local development Origins and one key digest.
- `site_example/production` has no DB policy.
- `site_disabled` has no DB policy; it remains excluded from Registry import.

This records only the local target. Each other deployment must inventory and reconcile its own DB and former TOML inputs before adopting the DB-only Collector.

## Implementation and validation

- Runtime refresh uses active Registry membership, rejects missing/disabled/archived policy, removes deleted or archived snapshots after a successful refresh, and preserves valid database snapshots across refresh outages.
- PostgreSQL integration coverage exercises active and disabled policy, absent policy despite legacy-looking credentials, archived Site removal and applied-state cleanup, key rotation, policy deletion and last-known-good outage behavior.
- Snapshot reconciliation unit tests cover invalid/conflicting policy retention with last-known-good and fail-closed behavior for first-time invalid/conflicting policies. PostgreSQL constraints reject malformed policy documents before they can reach Collector refresh.
- E2E setup now seeds Site Registry and ingest policy rows in PostgreSQL before starting Collector.
- Removed the runtime config option from Collector CLI, Compose, environment example and operations docs.
- Validation passed: Compose configuration validation, JavaScript syntax checks, Rust formatting, Collector unit tests, and the PostgreSQL integration scenario against an isolated temporary database. The Dashboard E2E was attempted but did not complete: after seeding its isolated PostgreSQL database, Compose service startup/build made no progress for more than five minutes. The test run was stopped and its containers and temporary volume were removed.

## Follow-up

M4.5 remains open for full compatibility acceptance across Processor, Analytics history/reporting, runtime status visibility and target-specific rollout. This closeout does not certify non-local deployments.

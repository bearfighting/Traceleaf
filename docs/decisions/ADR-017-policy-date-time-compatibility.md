# ADR-017: Enforce Schema date-time formats for stored environment policies

- Status: Accepted
- Date: 2026-09-29
- Related: [M2 configuration contract inventory](../m2-configuration-contract-inventory.md), [M2 implementation checklist](../m2-implementation-checklist.md), [M0b parity report](../m0b-step6-parity-report.md), [ADR-015](ADR-015-validation-lifecycle-and-staged-static-migration.md)

## Context

Stored Environment Policy V1 declares `updated_at` and each `ingest_keys[].created_at` as JSON Schema `date-time`. M0b added canonical invalid fixtures for both fields. Collector's policy Schema validator currently uses Draft 2020-12 without enabling format assertions, so `parse_database_policy` accepts those two invalid documents. The typed storage structs currently represent both timestamps as `String`.

The policy refresh path already handles invalid database documents by retaining the last valid policy and marking the policy identity stale. If no last-good value is present, the invalid policy is not applied. This behavior provides the compatibility boundary for enforcing the existing Schema contract.

## Decision

1. The stored policy Schema is authoritative: `updated_at` and `ingest_keys[].created_at` must satisfy JSON Schema `date-time`.
2. Before enabling format assertions in Collector, operators must set `DATABASE_URL` to each target deployment database and run the read-only preflight `node scripts/audit-policy-datetimes.mjs`. The script must fail closed if `DATABASE_URL` is missing, lacks a database name or explicit single hostname, or uses a multi-host URL. It must not fall back to libpq default host settings. It must ignore inherited libpq host, address, port, database, user, service, and target-session routing variables so the URL determines the destination, and force `target_session_attrs=read-write` so the audit runs against the writable primary. The script rejects a URL `target_session_attrs` parameter. The script must resolve the visible `site_environment_policies` relation through PostgreSQL catalogs using the target connection role, require it to be an ordinary or partitioned table with the expected identity/document columns, and quote its actual schema before querying. It must clear inherited `PGOPTIONS` and reject the URL `options` parameter so session settings cannot redirect table resolution. Repair `updated_at` findings by updating the policy; repair `created_at` findings by reviewing and performing key revocation/rotation through the existing key APIs.
3. The preflight must report policy identity and offending JSON field paths without printing timestamp values. It must run its database query in a read-only transaction.
4. Once strict validation is enabled, invalid rows use existing last-good/stale behavior. This ADR does not change that behavior, the API wire contract, or API timestamp writes.
5. M2.1 records the decision and preflight tool only. Enabling production format validation is deferred to M2.2/M2.4 and requires the preflight, canonical fixture tests, and parity verification.

## Consequences

- Persisted malformed timestamp strings that Collector previously accepted will no longer be eligible as new policy state after strict validation is enabled.
- Operators must check all deployed databases and repair findings before the validator behavior changes; M2.2 must not silently deploy strict validation without this gate.
- Existing API writes remain RFC3339 timestamps generated by the current server path.
- The checked policy fixtures provide regression cases for both invalid fields; valid policy fixtures continue to establish accepted formats.

## Alternatives considered

- **Keep Collector permissive and weaken the Schema:** rejected because these fields are timestamps and the current mismatch is accidental omission of format assertion, not an intentional compatibility contract.
- **Enable strict validation immediately without a preflight:** rejected because old stored documents could become stale on deployment without an opportunity to repair them.

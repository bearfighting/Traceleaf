# M0a：现状基线与共同语义

- Status: Accepted
- Date: 2026-09-28
- Scope: 现状证据、既有兼容行为、Site 与运行配置共同语义
- Related: [Platform Improvement Roadmap](platform-improvement-roadmap.md)、[Site identity and lifecycle (ADR-013)](decisions/ADR-013-site-identity-and-lifecycle.md)、[Runtime configuration authority (ADR-014)](decisions/ADR-014-runtime-configuration-authority.md)

## 结论摘要

M0a 完成了进入 M1、M2、M3 前所需的现状盘点与领域语义冻结。本文区分三类内容：**当前实现事实**（有代码、migration 或测试证据）、**已冻结目标语义**（尚待后续切片实现）和**延期决定**。本文不表示 Site Registry、归档或 Site 创建 API 已存在。

- M1 可以在保持现有路径与行为的前提下移动 Analytics 和管理模块；M0a 已建立现有管理 API 与 definition revision 行为的测试基线。
- M2/M9 的类型来源、未知字段规则及 CI 防漂移策略属于 M0b 的生成器/contract 试验；本阶段不预判其结果。
- M3/M4/M5 分别负责 Registry 迁移、配置权威切换和新 Site API；新 API 的具体 HTTP wire contract 在 M5 冻结。

## 已冻结的首版语义

稳定决策由 [ADR-013](decisions/ADR-013-site-identity-and-lifecycle.md) 与 [ADR-014](decisions/ADR-014-runtime-configuration-authority.md) 记录，摘要如下：

- 新 Site 使用服务端生成、稳定且不从名称/URL推导的 ID；名称可重复、可修改。新创建要求名称与 HTTP(S) 网站 URL；旧 Site 保留 ID，URL 缺失时进入 needs-attention，不从 Origin 静默补写。
- 一个 Site 可有多个 environment；onboarding 首个 environment 默认显示 `production`，但这是创建时显式提交的可修改值，不是协议或 Collector 的隐式默认。开发初始化使用 `development`。
- 新创建默认仅开启必需的 Page Views，其余已实现 capability 初始关闭并由管理员选择；服务端按 manifest 校验依赖。迁移现有 Site 必须保留其当前有效 capability 状态，不套用新建默认值。
- `lifecycle_status` 与推导出的 `setup_status` 分开。归档停止后续新事件并保留历史查询、key 摘要和审计；恢复不会自动开放 environment policy。物理删除/隐私删除不在首版范围。
- Site 创建幂等由客户端请求 ID、规范化请求摘要和 Site ID 关联实现。相同 ID/相同请求重试返回元数据但不重放明文 key；相同 ID/不同请求冲突。关联在 Site 生命周期内不设过期时间，归档不解除关联且 Site ID 不得重用。M5 冻结具体端点、字段、错误 envelope、摘要规范与非明文存储形式，不改变幂等保证。
- 部署级管理员凭据仅用于受信任管理环境；多用户认证/RBAC 另立设计。平台环境变量只配置基础设施与部署授权，不创建生产 Site 或 Site Ingest Key。seed 必须显式启用，`seed-init` 只创建本地配置，不造分析事件。
- Site URL 首版只做 HTTP(S) 语法校验和 Origin 规则校验。服务端可达性检查及域名所有权证明延期，需单独处理 SSRF/验证设计。

## 迁移与兼容要求

1. M3 回填候选 Site ID 的来源至少覆盖 `site_capability_configurations`、`site_environment_policies`、`site_definition_revisions`、历史 raw events 与 derived facts、`DASHBOARD_SITES`/`DASHBOARD_DEFAULT_SITE`、Collector TOML Site/environment 项。开发环境另核对旧 `dev-seed` 的输入配置；这些环境变量/TOML/seed 值只作为一次性迁移清点输入，不保留运行时权威。来源重叠时合并成一个 Site，保留每一来源的核对数量和差异报告。
2. 迁移保留现有 Site ID、原始事件、事实/聚合、definition revision 与审计记录。未知 URL/名称明确标记待补充；Origin 只可作为 UI 建议。
3. 有效 DB policy 的旧 Site 在切换期间持续采集。M4 移除 TOML fallback 后，无 DB policy 的 Site 可查询历史数据但不能接收新事件；在 M4 切换前，缺失 DB 行仍可能由现有 TOML fallback 提供策略，必须在移除 fallback 前核对。数据库暂时不可用时已运行 Collector 可按当前 last-known-good stale 规则运行；切换后的策略明确不存在/停用/归档时 fail closed。
4. TOML fallback 在 M4 切换前可作为显式兼容来源；迁移必须核对 TOML site/environment、allowed origins 与 ingest key 后再移除，且删除 DB 行不能使 TOML key 再次生效。
5. `ANALYTICS_DEFINITIONS_FILE` 显式导入及一次性 seed 均须标注迁移/开发来源，不等同常规 Site Management 写入。普通 Processor 处理循环不得从文件覆写当前 definitions。
6. configuration runtime state 表在迁移中按运行状态处理；它们不能创建 Site，也不能作为 Site Registry 的权威来源。

## M0a 测试基线与缺口

已有测试已覆盖管理鉴权、If-Match/If-None-Match、版本冲突与并发、key 明文只在创建响应中出现、digest 不回传/不写 audit、definition immutable revisions 与按版本查询历史报表。本次在 `definition_sets_append_immutable_revisions_with_etags_and_reject_removal` 增加公开 revision-list 响应的 site ID、当前版本和排序断言，作为 M1 模块搬迁回归基线。验证已运行 `cargo fmt --check`、`pnpm format:check:docs`，以及 `cargo test -p analytics-api --test http definition_sets_append_immutable_revisions_with_etags_and_reject_removal -- --ignored --exact --test-threads=1`。

以下行为没有当前 Site Registry 实现和测试，不能称为已兼容：旧 Site 回填与重复迁移、归档/恢复、Site 创建原子性/幂等、站点 URL 元数据更新、DB/TOML 切换、seed flag 的空站点入口。它们分别由 M3、M4、M5、M6 提供测试。M0a 不扩展成完整的新 Site API 合同测试。

## 延后决策

- M0b：事件与配置各选一个代表性 contract 做类型生成试验；决定按类别使用生成或手工模型、未知字段策略和 CI 防漂移门禁。
- M5：新 Site list/detail/create/update HTTP 请求与响应、稳定错误编码、ETag/并发、幂等摘要规范化和审计事件 contract；请求 ID 的保留保证已由 ADR-013 冻结。
- M3/M4：Registry migration/importer 的具体运维执行、回滚策略和 TOML fallback 的具体过渡开关与移除版本。
- 独立后续设计：站点所有权验证、服务端可达性 probe、多用户 RBAC、物理删除及隐私删除。

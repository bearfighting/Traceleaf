## Remaining operational gate

- [ ] Run the preflight against every deployment database and record the result and any remediation before M2.2/M2.4 enables format assertion. No deployment database has been audited as part of this local work.

Before M2.2/M2.4 enables format assertion in production, set `DATABASE_URL` to each target deployment database and run `node scripts/audit-policy-datetimes.mjs`. The read-only audit covers both `site_environment_policies` (`document.updated_at` and each `document.ingest_keys[].created_at`) and `site_capability_configurations` (`document.updated_at`). It reports site/environment identity and JSON field paths without timestamp values. Repair invalid policy timestamps through the supported policy update path; for malformed key creation timestamps, review the key's rotation or revocation through the supported management path. Repair invalid capability timestamps through the supported capability configuration write path. Rerun the audit and record the deployment target, date, aggregate findings, and remediation status without recording credentials or timestamp values.

The script fails closed when `DATABASE_URL` is missing or lacks a database name, explicit hostname, or single-host target. It ignores inherited libpq routing variables and requires a writable primary. It resolves exactly one matching table for each required table name from PostgreSQL catalogs, verifies each table kind and required columns, and quotes each schema before reading. It clears inherited `PGOPTIONS` and rejects URL `options` and `target_session_attrs` to keep the target and SQL context fixed. Local fixture verification and the disposable PostgreSQL exercise recorded in the [M2.4 parity assessment](m2.4-configuration-parity.md) are not deployment database audits. The offline checker command is `node scripts/audit-policy-datetimes.mjs --fixtures`.
